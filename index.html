wavves

In the wavves package, you get the wavves skills with a blank template for every workspace file. Every wavves word keeps its name so you can read the plain meaning of each one in the README.

With /remeasure, an agent's "done" becomes a gate with a claim and a check someone else can rerun. Each gate records the raw output along with a grade from someone other than the author.

A fresh thread runs the pickup check in /mod-rotate on receiving a handoff. Five recovery playbooks give a fix row for every message in the output of either script.

A rotation history audit run in /mod-rotate reads every rotation file in a repo in order. Gaps in the numbering and breaks in the chain of terms each get an ERROR line.

Running any script in the wavves package takes Python 3 and no other packages. The pickup commit checks and every rotation history audit run also need a local git binary.

The wavves control surface

In the wavves workflow the moderator keeps the plans and results for every lane of work as plain files under one wavves folder. On screen INDEX.md comes first, followed by the lane folders of the sample repo. Inside one lane the moderator keeps a waveset, the plan file with the waves and gates of the lane. A wave is one batch of parallel agents that the moderator checks before the next wave opens. At the end you reach the rotations folder, where the moderator writes one rotation file for each handoff to the next moderator term in a new thread. You start the same folders in your own repo from the blank templates in the wavves package.

Demo charter 02 with a check followed by a kick

In demo charter 02 the workers check a written spec and the moderator locks two decisions before the feature gets built in waves. The workers fail one gate on the first try and pass the same gate after one repeat. At the end the moderator does a kick, a move of the work to another machine with a published allowlist and a short paste.
