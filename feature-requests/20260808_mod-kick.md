## Problem

After a waveset lands (or INT is ready), the operator often wants to **leave
this Cursor environment** and continue in another agent / machine / modality
(voice readback, phone, separate workspace). Today that requires:

1. Remembering to commit + push the right surfaces
2. Hand-writing a one-liner that cites hashes, paths, and next asks
3. Guessing which repo(s) the successor can see

`/mod-rotate` solves a different problem: **same orchestrator continuity**
into a fresh thread (rotation file, `O0.R(N+1)`, standing `wavves/AGENTS.md`).
It does not define an **environment exit** product for arbitrary successor
agents that only share git remotes.

**Fail id (proposed):** `PROC-KICK-NO-PUBLISH` — kick paste emitted while
pickup paths are local-only / unpushed.

**Fail id (proposed):** `PROC-KICK-MULTI-SILENT` — kick assumes multi-repo
hydration without recording clear operator auth of each remote.

**Fail id (proposed):** `PROC-KICK-VENDOR-SILENT` — kick copies or vendors
paths from a secondary repo into the pickup lane without explicit auth.

## Feature sketch (KICK)

| id | target | change |
|---|---|---|
| KICK-01 | `mod-kick` | On `/mod-kick`, **publish first**: stage lane-owned surfaces per repo protocol, commit if protocol allows (or emit commit plan + wait), **push** pickup remotes, verify `origin` sync. Refuse paste until publish PASS (or operator overrides with `LOCAL_ONLY` labeled paste). |
| KICK-02 | `mod-kick` | **Single question by default:** `Pickup repo?` Propose default = lane `repos:` primary (or sole dirty repo). Operator may accept default with shrug / proceed. |
| KICK-03 | `mod-kick` | **Multi-repo:** if hydration needs >1 remote, list each repo + required commit hash + why. Proceed only after explicit auth (`MULTI_REPO_AUTH` or per-repo yes). Never silently require three remotes. |
| KICK-04 | `mod-kick` | **Prefer single-repo pickup:** when secondary remotes hold only thin tracked deps (few files, already cited by hash), offer `VENDOR_INTO_PICKUP`: copy/vendor those paths into the pickup lane home (or `desktop_staging` / `findings/deps/`) under **explicit auth**, then kick against **one** repo. Record vendored source hash + paths in kick receipt. |
| KICK-05 | `mod-kick` | Emit a **paste-ready one-liner** (and optional short block) for the successor: pull pickup repo @ hash; read-order of files; locks; operator gate; “discuss / readback OK.” Optimized for read-aloud and for agents that only have that repo. |
| KICK-06 | `mod-kick` | Write durable receipt: `<lane>/moderator_handoffs/KICK_<YYYYMMDD>_<HHMM>.md` (or `wavves/kicks/` when no lane) with pickup repo, hashes, file read-order, multi/vendor auth lines, paste body. |
| KICK-07 | router / usage | Register `/mod-kick` next to `/mod-rotate`. Document: rotate = same O0 family continuity; kick = cross-environment exit + remote pickup. |
| KICK-08 | evals | Fixture: paste without push → FAIL `PROC-KICK-NO-PUBLISH`. Fixture: multi-repo without auth block → FAIL `PROC-KICK-MULTI-SILENT`. Fixture: vendor without auth → FAIL `PROC-KICK-VENDOR-SILENT`. |

### Default operator UX

```text
/mod-kick

Pickup repo? [default: applications-for-jobs]
  A) accept default (single-repo)
  B) name another single repo
  C) multi-repo (list + auth required)
  D) single-repo + vendor thin deps from <other> (VENDOR_AUTH required)

→ publish → paste one-liner → this environment done for that stream
```

### Paste contract (minimum)

Successor one-liner MUST include:

1. Pickup repo identity + full commit hash
2. Ordered read list (return / rankings / queue / adversarial / Ready drafts)
3. Standing locks (ledger, prose, no-send, etc. as applicable)
4. Operator next move (e.g. role-by-role APPROVE/HOLD/REJECT)
5. Permission to use readback / discuss modality

Optional second line only if MULTI_REPO_AUTH or VENDOR_AUTH was used (cite receipt path).

### Explicit non-goals

- Not a substitute for `/mod-rotate` (no successor term assignment, no
  rotation file shape unless operator also rotates).
- Not Desktop-only delivery; Desktop may be noted as local supplement, but
  kick authority is **git-published** pickup.
- Not auto-submit / not auto-send outbound apps.
- Not silent vendoring of large secondary trees (thin deps only; else multi-repo auth).
