## Problem

After a waveset lands (or INT is ready), the operator often wants to **leave
this Cursor environment** and continue in another agent / machine / modality
(voice readback, phone, separate workspace). Today that requires ad-hoc
commit/push and a hand-written one-liner.

`/mod-rotate` = **same orchestrator family** continuity (`O0.R(N+1)`, rotation
file, hydrate via existing **`pickup` playbook**).

`/mod-kick` = **cross-environment exit** for an arbitrary successor that shares
**git remotes** only. Kick is **not** the `pickup` playbook (that word stays
owned by rotate-hydrate). Prefer wording **target repo** / **kick target** in
UX; “pickup repo” only as a synonym in receipts, never as a router leave-act.

**Fail ids (ship):**

| id | Meaning |
|---|---|
| `PROC-KICK-NO-PUBLISH` | Paste claims remote pull while surfaces are local-only / unpushed |
| `PROC-KICK-MULTI-SILENT` | Multi-remote hydration without recorded `MULTI_REPO_AUTH` |
| `PROC-KICK-LEASH-SILENT` | Leash (thin copy-in) without recorded `LEASH_AUTH` |
| `PROC-KICK-LOCAL-ONLY-ABUSE` | `LOCAL_ONLY` used for cross-env handoff (other machine / no shared FS) |
| `PROC-KICK-WRONG-DEFAULT` | Proposed default ≠ lane `repos:` primary (or sole listed repo) |
| `PROC-KICK-UNRELATED-PUSH` | Publish outside lane-owned allowlist for the kick stream |
| `PROC-KICK-SECRET-LEAK` | Leash or paste includes `.env*`, credentials, or secret substrings |
| `PROC-KICK-DESKTOP-AUTHORITY` | Desktop / `desktop_staging` cited as kick authority instead of git hash |
| `PROC-KICK-ROTATE-COLLAPSE` | Kick cues routed to rotate (or reverse) without explicit dual-invoke |
| `PROC-KICK-LEASH-UNBOUNDED` | Leash without closed thin threshold (over ≤8 files / ≤256 KiB) |
| `PROC-KICK-SHRUG-WIDEN` | Bare shrug / proceed accepts MULTI or LEASH without explicit auth lines |

### Default operator UX

```text
/mod-kick

Kick target repo? [default: <lane repos: primary or sole listed>]
  A) accept default (single-repo)
  B) name another single repo
  C) multi-repo (list + MULTI_REPO_AUTH required — shrug does NOT accept)
  D) single-repo + leash thin deps (LEASH_AUTH + thin threshold — shrug does NOT accept)

→ publish allowlist → paste one-liner → this environment done for that stream
```

### Paste contract (minimum)

1. Kick-target repo identity + full commit hash  
2. Ordered read list **derived from the lane** (e.g. orch return → rankings → NEEDS_REVIEW → adversarial → Ready drafts; or waveset → findings → decisions — whatever the lane owns)  
3. Standing locks as applicable  
4. Operator next move  
5. Readback / discuss modality OK  

If `MULTI_REPO_AUTH` or `LEASH_AUTH`: second line cites receipt path.

### Explicit non-goals

- Not a substitute for `/mod-rotate` / `pickup` hydrate  
- Not Desktop-as-authority (`PROC-KICK-DESKTOP-AUTHORITY`)  
- Not auto-submit / outbound send  
- Not silent large-tree leash  
- Not combined kick+rotate in one silent path (dual-invoke must be explicit and ordered: publish kick first, then rotate, or refuse)
